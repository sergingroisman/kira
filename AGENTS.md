## Overview

**Kira** is Sergin's personal agentic harness. Codename from Death Note (silent agent). Architectural inspiration: **Spektor** (treated as inspiration, not blueprint — we diverge when it makes sense for solo dev). Core thesis: **Chinese-stack sovereignty** — zero Anthropic/OpenAI on the critical path.

**Full plan**: `/Users/avanade/.claude/plans/users-avanade-documents-sergin-doc-vaul-mellow-moler.md`

**Hybrid architecture**:
- `agent/` — TypeScript + Bun + Ink REPL (client, UX, streaming view).
- `core/` (to be created) — Rust daemon (`axum` HTTP+SSE on `127.0.0.1:7777`). Hot path, durable state, agents, tools, text pipeline.

The REPL talks to the core via local HTTP `/v1/*` + SSE for streaming. Shared types are generated by the `ts-rs` crate into `agent/src/generated/`.

## Operating Principle (read first)

> *"The difference between 'in the loop' and 'on the loop' shows up when you don't like the result. People on the loop change the harness that produced the artifact."* — Kief Morris

When agent output is bad, **do not edit the output**. Edit one of:
1. **Workflows** in `.kira/workflows/*.yaml` (v0.5+)
2. **Prompts** in `core/agents/prompts/*.md`
3. **Hooks** in `kira-core.toml`
4. **Tokens / thresholds** in `tokens.toml`

The harness is the product. Output is a consequence.

## Build & Run

### REPL (TypeScript + Bun)

```bash
cd agent/
bun install
bun run src/cli/index.tsx                                              # dev
bun build src/cli/index.tsx --compile --outfile=../dist/kira-repl      # single binary
```

Target runtime: **Bun**. Node 22+ is fallback only (`.nvmrc`).

### Core daemon (Rust)

```bash
cd core/
cargo run                          # dev (default port 7777)
cargo run --release                # optimized
cargo build --release              # binary at target/release/kira-cored
cargo test                         # unit + integration tests
cargo clippy -- -D warnings        # strict lint, must pass
cargo fmt --check                  # formatting check
```

Prereqs: `rustc 1.95+` stable (`rustup install stable`). Mac aarch64 or Linux x86_64.

### Full dev workflow

- Terminal 1: `cd core && cargo run` (daemon stays up)
- Terminal 2: `cd agent && bun run src/cli/index.tsx` (REPL)

The REPL points to `http://127.0.0.1:7777/v1/` by default.

## Rust Conventions (`core/`)

- **Errors**: `anyhow::Result<T>` everywhere in v0. Use `thiserror` only in libraries you intend to publish (v0.5+).
- **Async**: `#[tokio::main]` in `main.rs`. Use `async fn` freely. Avoid `async-trait` — prefer native `impl Trait in trait` (Rust 1.75+).
- **Concurrency**: prefer `tokio::sync::mpsc` channels over `Arc<Mutex<T>>` when possible. Fewer deadlocks.
- **Lifetimes**: prefer `String` over `&str` and `Vec<T>` over `&[T]` in structs. Add lifetimes only when the compiler demands.
- **Logs**: `tracing` + `#[instrument]` on handlers. No `println!` in production code.
- **No literals**: zero hardcoded numbers, URLs, or paths in source. Everything via `tokens.toml`.
- **No `unsafe`** in v0. Place `#![forbid(unsafe_code)]` in `lib.rs`.

### Common patterns

```rust
// Error propagation with ? operator
pub async fn route(&self, req: RoutingRequest) -> anyhow::Result<ChatStream> {
    self.budget.check()?;                                  // hard stop
    let candidates = self.candidates_for(&req)?;
    for cand in candidates {
        if self.breakers[&cand.key()].is_open() { continue; }
        match self.clients[&cand.provider].chat(&cand.model, &req).await {
            Ok(stream) => return Ok(stream),
            Err(e) if is_retryable(&e) => continue,
            Err(e) => return Err(e),
        }
    }
    anyhow::bail!("all providers exhausted for tier {:?}", req.tier)
}

// Idiomatic state machine via enum + match
pub enum WorktreeStatus { Spawning, Idle, Active, Stale, Completed, Failed, Cleaning, Destroyed }
match wt.status {
    WorktreeStatus::Stale => self.release_permit(&wt),
    WorktreeStatus::Completed => self.schedule_cleanup(&wt),
    _ => {}
}

// Tokens loaded once, shared via Arc
let tokens = Arc::new(Tokens::load("tokens.toml")?);
```

## TypeScript Conventions (`agent/`)

- **Runtime target**: Bun. Node compatibility where possible.
- **UI**: Ink (React for the terminal). Streaming via `useEffect` + `AsyncIterable`.
- **HTTP**: native Bun `fetch`. SSE via `EventSource` (Bun native).
- **Shared types**: import from `agent/src/generated/` (produced by `ts-rs` during `cargo test` in core).
- **No `any`**. Use `unknown` plus narrowing.
- **Errors**: discriminated unions (`type Result<T,E> = {ok:true,value:T} | {ok:false,error:E}`) or the `neverthrow` library.

## Sub-agents (v0)

Three kinds. Each is a `tokio::spawn` task inside the core process, runs in its own git worktree with strict file ownership.

| Kind | Tier | Owns (FS) | System prompt | Limits |
|---|---|---|---|---|
| `writer` | Standard | `src/content/**`, `public/**` | `core/agents/prompts/writer.md` | max_iters=50, budget=$1, timeout=1h |
| `deployer` | Light | `scripts/deploy.sh`, `dist/**` | `core/agents/prompts/deployer.md` | same defaults |
| `judge` | Heavy (read-only, writes only `eval_runs`) | — | `core/agents/prompts/judge.md` | `judge_model ≠ writer_model` **required** (self-enhancement bias) |

**Coordination v0**: Star (core orchestrates). Agents communicate with the core only, via FS mailbox at `.kira/mailbox/<agent_id>/{inbox,outbox}/`.

**v0.5 migration**: introduce Pilot (M15) + Orchestrator (M16) hierarchy. Add SDD 4-phase pipeline (SPECIFY → DESIGN → TASKS → EXECUTE) with auto-sizing for trivial bug fixes.

## Hooks Contract

Configured in `kira-core.toml`:

```toml
[[hooks]]
event = "PreToolUse"
matcher = { tool = "bash", regex = "rm -rf" }
command = ["sh", "-c", "echo 'BLOCKED: dangerous rm' >&2 && exit 1"]
timeout_secs = 5

[[hooks]]
event = "PostToolUse"
matcher = { tool = "file_write", path_glob = "**/*.rs" }
command = ["cargo", "fmt", "--", "{{file}}"]
timeout_secs = 30
```

v0 events: `SessionStart`, `PreToolUse` (block-capable), `PostToolUse`, `WorktreeSpawn`, `WorktreeDestroy`, `BudgetWarn`, `BudgetStop`.

Output schema (mixed exit code + optional JSON):
- Exit `0` → continue.
- Exit `≠0` → cancel operation (PreToolUse only). Stderr goes to core log.
- Valid JSON on stdout → `{action, message, modified_input?}` (advanced v0.5+).

## Security Rules (OWASP-aligned)

Full controls (SC1–SC12) are documented in the plan. Apply these **always**:

| # | Rule | Mechanism |
|---|---|---|
| 1 | Prompt injection isolation | XML delimiters: `<SYSTEM_INSTRUCTIONS>` vs `<USER_DATA>` vs `<TOOL_OUTPUT>` vs `<RAG_CONTEXT untrusted>`. Anything outside SYSTEM_INSTRUCTIONS is data, never command. |
| 2 | Tool risk classification | Every tool call labelled LOW / MEDIUM / HIGH / CRITICAL. HIGH+ requires approval. CRITICAL halts. |
| 3 | OS command injection | `bash` tool uses an executable allowlist + arg regex + no shell expansion. Always `tokio::process::Command::args(&[...])` with separate arguments. |
| 4 | Path traversal | `std::fs::canonicalize()` before any FS op. Reject if the canonical path does not match the expected prefix. |
| 5 | Secrets | `.env` chmod 600, gitignored. Log redaction for `*_KEY`, `*_TOKEN`, `*_SECRET`. Pre-commit hook scans for leaks. |
| 6 | Audit integrity | JSONL with CR/LF sanitisation. Append-only. ISO timestamps. No PII / API keys in audit fields. |

## Operating Philosophy

- **Chinese sovereignty first**: defaults are always DeepSeek/Qwen. OpenRouter only when explicitly enabled for eval.
- **On the loop**: edit the harness, not the output.
- **Worktrees are disposable**: durable state lives in `redb` and `audit/`, never in the worktree.
- **Tokens are expensive, agents are cheap**: prefer spawning two Light-tier sub-agents over one Heavy when it makes sense.
- **Caveman compressor (M19) applied**: long prompts, lessons, and transcripts go through compression before injection.
- **Fail closed**: when risk classification, budget guard, ownership lookup, or audit logging fails — halt, do not default-allow.
